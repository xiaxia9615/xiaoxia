# ADR-0001: 采用模块化单体架构

## 状态

已采纳（2026-10）

## 背景

项目包含 User / Product / Skill / Ledger / AiProvider / Team 等多个领域。
纯单体代码易腐化，微服务对个人项目是过度设计。

## 决策

采用模块化单体：
- 每个模块独立命名空间 `App\Modules\{Module}`
- 模块间依赖通过 `config/modules.php` 白名单声明
- 架构守卫 `tests/Architecture/` 自动拦截越界引用

## 后果

- 正面：代码边界清晰，可独立演进，单机部署成本低
- 负面：模块间通信仍是进程内调用，未来拆微服务需重构
- 约束：新增跨模块依赖必须走白名单 + 架构测试

## 替代方案

- 微服务：个人项目过度设计，运维成本高
- 纯单体：代码易腐化，半年后无法维护
